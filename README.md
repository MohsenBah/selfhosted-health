# Self-Hosted Health

**Own the store. Treat every wearable as a disposable feeder.**

A demo-ready stack that keeps your health and gym data on infrastructure you control:

| Layer | Component | Role |
|---|---|---|
| **Wearables hub** | [Open Wearables](https://github.com/the-momentum/open-wearables) | Ingest + normalize Garmin, Polar, Oura, Apple HealthKit, … |
| **Gym tracker** | [wger](https://github.com/wger-project/wger) behind **nginx** | Daily lifting, routines + Flutter phone app |
| **Show layer** | Grafana | Join both Postgres databases — no app-to-app sync |
| **Insurance** | `scripts/backup.sh` | Nightly `pg_dump` so a dead upstream is not a dead archive |

```
Garmin / Polar H10 / (later Oura, HealthKit)
        │
        ▼
┌───────────────────┐     ┌──────────────┐
│  Open Wearables   │     │     wger     │◄── you at the gym (Flutter)
│  (Postgres)       │     │  (Postgres)  │
└─────────┬─────────┘     └──────┬───────┘
          │                      │ nginx :8080  ← open this (or via NPM)
          │                      │ gunicorn :8000 (internal only)
          └──────────┬───────────┘
                     ▼
              ┌─────────────┐
              │   Grafana   │  demo dashboards (compose or existing)
              └─────────────┘
                     │
                     ▼
              pg_dump archive  ← what you actually own
```

## Why this shape

- **All data first** — Open Wearables stores generic time series even for metrics you never chart.
- **Swap gadgets** — add Oura or Polar without changing the gym app or the archive format.
- **No redundant sync** — sleep/HRV/steps have nowhere useful in wger; body weight is the only real overlap. Join in Grafana instead of copying rows.
- **Not a map app** — FitTrackee and outdoor GPX archives are out of scope here.
- **Show-off friendly** — one `docker compose` story for demos: wearables API + gym UI + Grafana.

Upstream licenses stay upstream (Open Wearables MIT, wger AGPL-3.0). This repo is glue, docs, and Grafana provisioning (MIT).

## Quick start

```bash
git clone <your-fork-or-path> selfhosted-health && cd selfhosted-health
./scripts/bootstrap.sh
```

Then edit the **three env files** below, bring the stack up, and open the URLs.

### Env files (read this once)

| File | Who reads it | You must set |
|---|---|---|
| **`.env`** (repo root) | Docker Compose (ports, DB passwords for *containers*) | `OW_DB_PASSWORD`, `WGER_DB_PASSWORD`. `GRAFANA_*` only if you use `--profile grafana` / `full` (safe to omit with an external Grafana). For LAN or reverse-proxy demos, set `OW_PUBLIC_API_URL` to the URL the **browser** will call (see NPM below). |
| **`open-wearables/.env`** | Open Wearables *app* containers | `ADMIN_EMAIL`, `ADMIN_PASSWORD`. `SECRET_KEY` is generated by bootstrap. **`DB_PASSWORD` must equal `OW_DB_PASSWORD`** — re-run `./scripts/bootstrap.sh` after changing root `.env` to sync it. Match `FRONTEND_URL` / `CORS_ORIGINS` to the UI origin you open. |
| **`wger/config/prod.env`** | wger web / worker / beat | Created by bootstrap. DB password lines are re-synced from `WGER_DB_PASSWORD` when you re-run bootstrap. Set `SITE_URL` / `CSRF_TRUSTED_ORIGINS` to the URL you open (LAN or `https://gym.<your-domain>.com`). |

`open-wearables/README.md` is only a short reminder; **the table above is the source of truth.**

### Bring it up

```bash
docker compose --profile full up -d --build
```

First Open Wearables build can take several minutes. **First wger boot** (migrate + collectstatic) often takes **5–10+ minutes** on a small CT — `sh-wger-web` will sit in `health: starting` that whole time. Worker and nginx wait until web is healthy.

### URLs (what to open)

| Service | URL | Notes |
|---|---|---|
| Open Wearables UI | http://localhost:3000 | |
| Open Wearables API docs | http://localhost:8000/docs | |
| **wger (use this)** | **http://localhost:8080** | **nginx** fronts static/media + proxies to gunicorn. Do not publish raw wger `:8000`. |
| Grafana | http://localhost:3001 | admin / password from `.env` (compose Grafana only) |

On a remote host, replace `localhost` with the host IP (e.g. `http://<host-ip>:8080`).

### Profiles

| Profile | What starts |
|---|---|
| `wearables` | Open Wearables only (trimmed: no Flower, no Svix) |
| `gym` | wger only (db, redis, web, worker, beat, **nginx**) |
| `grafana` | Grafana only (expects DBs already up) |
| `full` | Wearables + wger + Grafana |

```bash
docker compose --profile wearables up -d --build
docker compose --profile gym up -d
docker compose --profile wearables --profile gym up -d --build   # apps only (no compose Grafana)
docker compose --profile full up -d --build
```

### Nginx Proxy Manager (optional)

Compose already runs a **wger nginx sidecar** for static/media. **NPM** (or any reverse proxy) is only the **named HTTPS edge** in front of published ports — it does not replace that sidecar.

Suggested proxy hosts (pick names on **`<your-domain>.com`**):

| Proxy host (example) | Forward to | Notes |
|---|---|---|
| `https://gym.<your-domain>.com` | `http://<host-ip>:8080` | **wger** — usual candidate to publish |
| `https://wearables.<your-domain>.com` | `http://<host-ip>:3000` | OW UI — often keep LAN-only |
| `https://wearables-api.<your-domain>.com` | `http://<host-ip>:8000` | OW API — required if OW UI is HTTPS |

When the UI is HTTPS, the browser **cannot** call a plain `http://<host-ip>:8000` API (mixed content). Set:

```bash
# root .env
OW_PUBLIC_API_URL=https://wearables-api.<your-domain>.com

# open-wearables/.env
FRONTEND_URL=https://wearables.<your-domain>.com
CORS_ORIGINS=["https://wearables.<your-domain>.com"]
```

Then recreate `ow-frontend` / `ow-app`.

For wger behind NPM HTTPS, in `wger/config/prod.env`:

```bash
SITE_URL=https://gym.<your-domain>.com
CSRF_TRUSTED_ORIGINS=https://gym.<your-domain>.com,http://<host-ip>:8080
X_FORWARDED_PROTO_HEADER_SET=True
USE_X_FORWARDED_HOST=True
NUMBER_OF_PROXIES=2
```

Recreate `wger-web`, restart `wger-nginx`, then flush Redis so cached API image URLs become `https://…`:

```bash
docker compose --profile gym up -d --force-recreate wger-web
docker restart sh-wger-nginx
docker compose exec wger-cache redis-cli FLUSHALL
```

Never put Postgres (`5432` / `5433`) on NPM.

### Existing Grafana (skip compose Grafana)

If you already run Grafana elsewhere (e.g. on-demand / Wake-on-LAN host), start **only** `wearables` + `gym`, leave Postgres ports reachable to that Grafana, and add two PostgreSQL datasources. Step-by-step: **[docs/existing-grafana.md](docs/existing-grafana.md)**.

## If `sh-wger-web` stays “creating” then fails

Nginx and the Celery worker **will not start** until web is healthy — that is expected.

```bash
# Watch first-boot progress (migrations / collectstatic)
docker compose logs -f wger-web

# Common fix: password drift between root .env and prod.env
./scripts/bootstrap.sh   # re-syncs WGER_DB_* into wger/config/prod.env
docker compose --profile gym up -d --force-recreate wger-web

# Still dead? inspect exit reason
docker inspect sh-wger-web --format '{{.State.Status}} {{.State.Health.Status}} {{.State.OOMKilled}}'
```

Prefer **2 vCPU / 4 GiB RAM / 1 GiB swap** for wearables + gym (or **3 GiB** RAM once stable). A 2 GiB box often OOMs or times out the wger healthcheck. Details: [docs/homelab-placement.md](docs/homelab-placement.md).

## Backup (the part that matters)

```bash
./scripts/backup.sh ./backups
# produces timestamped dumps of both Postgres databases
```

Restore is documented in the script header. Schedule this from cron or your CT backup job — **the dumps are the durable asset**, not the container images.

## What this is not

- Not a medical device / not clinical advice.
- Not a Strava/Garmin Connect replacement for social features.
- Not “sync Open Wearables into wger” — that path is deliberately rejected (see architecture doc).
